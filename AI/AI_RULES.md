> **КРАЙНЕ ВАЖНЫЙ РЕГЛАМЕНТ ДЛЯ ЛЮБОГО НОВОГО АГЕНТА:**
> Пользователь отправляет ссылку на этот репозиторий в GitHub **ТОЛЬКО ОДИН РАЗ** при первом подключении агента.
> Постоянно обращаться к GitHub при каждом новом сообщении или ответе **СТРОГО ЗАПРЕЩЕНО** во избежание траты времени, токенов и лимитов API.

### 📋 Пошаговый алгоритм первого запуска:
1. **Первый вход по ссылке:** Агент переходит по отправленной пользователем ссылке, считывает Шаг 1 (`AI_RULES.md`) и Шаг 2 (целевой модуль своей среды).
2. **Локальное сохранение в персональную песочницу:**
   - Агент **ОБЯЗАН немедленно сохранить эти правила локально у себя в папке на диске `C:`**:
     - `C:\AI\<ИМЯ_ИИ>\RULES.md` (например, `C:\AI\GEMINI\RULES.md`, `C:\AI\CLAUDE\RULES.md`, `C:\AI\ChatGPT\RULES.md`, `C:\AI\VSCode\RULES.md`).
     - При необходимости также продублировать в файл нативной конфигурации (`CLAUDE.md`, `.cursorrules`, `.windsurfrules`, `.copilot-instructions.md`).
3. **Подтверждение пользователю:**
   - Агент даёт краткий ответ:
     > *«Правила изучены и сохранены локально в `C:\AI\<ИМЯ_ИИ>\RULES.md`. В дальнейшем работаю автономно с локальной копии без повторных запросов к GitHub.»*
4. **Автономная работа без обращений к GitHub:**
   - При всех последующих сессиях и ответах агент считывает правила **строго из своего локального файла** и общей базы `C:\AI\BASE\`.
5. **Регламент обновления правил (Ручной триггер):**
   - Агент повторно обращается к GitHub за правилами **ТОЛЬКО ТОГДА, когда пользователь вручную ещё раз явно отправит его в репозиторий** с указанием обновить правила.

## 📁 РАЗДЕЛЕНИЕ ПАПОК И ИЗОЛЯЦИЯ СРЕДЫ (`C:\AI\`)

На рабочем компьютере создаётся единая структура на диске `C:`:
1. 🏠 **Персональные песочницы каждого ИИ:**
   - `C:\AI\GEMINI\` — для Google Gemini / Antigravity
   - `C:\AI\CLAUDE\` — для Claude Desktop / CLI
   - `C:\AI\ChatGPT\` — для ChatGPT / OpenAI Codex
   - `C:\AI\VSCode\` — для VS Code AI и Continue
   - `C:\AI\Cursor\` — для Cursor IDE
2. 🚫 **СТРОГИЙ ЗАПРЕТ НА ВМЕШАТЕЛЬСТВО В ЧУЖИЕ ПАПКИ:**
   - Категорически запрещено удалять, изменять или перемещать папки чужих интеллектов.
   - Каждый интеллект создаёт рабочие и временные файлы **исключительно внутри своей выделенной папки**.
   - **Запрет на мусор в корне:** в корне `C:\AI\` должны быть только целевые каталоги.

## 🧠 ОБЩАЯ БАЗА ЗНАНИЙ ДЛЯ ВСЕХ ИНТЕЛЛЕКТОВ (`C:\AI\BASE\`)

На диске `C:` организуется общая база знаний: **`C:\AI\BASE\`**.
1. **Единый источник правды:** Базу используют **ВСЕ интеллекты** для быстрого получения сведений о структуре проектов, серверах и общих инструкциях.
2. **Безопасность данных (Append-Only):**
   - Все интеллекты имеют право **ТОЛЬКО ДОБАВЛЯТЬ новую актуальную информацию**.
   - **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО УДАЛЯТЬ ЧУЖИЕ ДАННЫЕ И ФАЙЛЫ ИЗ ПАПКИ `BASE`!**
3. **Токен-эффективная маршрутизация (Fast Router):**
   - В корне базы создаётся навигационный файл `C:\AI\BASE\INDEX.md` (~40 строк, < 200 токенов).
   - ИИ сначала считывает `INDEX.md`, определяет нужный раздел и читает строго один целевой файл (< 50 строк), избегая полного дампа базы в контекст.

## 🚨 ФУНДАМЕНТАЛЬНЫЕ ПРАВИЛА ЭКОНОМИИ ТОКЕНОВ (TOKEN ECONOMY & ZERO WASTE)

### 1️⃣ ПРАВИЛО №1: СТРОГО ПО ДЕЛУ И НИКАКОЙ ВОДЫ
* Писать предельно лаконично, емко, без вводных фраз, избыточной вежливости и повторных приветствий («Привет», «Здравствуйте»).
* Принцип **«Один чат — одна задача» (`Ctrl+N`)**: под каждую новую задачу открывать свежий чат, сохраняя 90–95% токенов контекста.
* Не выполнять действий, о которых пользователь явно не просил (запрещены спонтанные рефакторинги, переписывание несвязанного кода).

### 2️⃣ ПРАВИЛО №2: ТОЧЕЧНАЯ РАБОТА С ФАЙЛАМИ (SLICE-ONLY READING)
* **Запрещено читать файлы целиком**, если они превышают 100 строк.
* Использовать `grep_search` / `Select-String` для поиска строк и срезы строк (`StartLine` / `EndLine` по 50–100 строк).
* Большой код, конфиги и скрипты сохранять **сразу в целевые файлы на диске**. В чат выдавать только краткую сводку и путь к файлу (никаких многостраничных дампов в окно диалога).

### 3️⃣ ПРАВИЛО №3: ПОЛНАЯ АВТОНОМНОСТЬ (DO IT YOURSELF FIRST)
* Если агент обладает инструментами (терминал, вызов команд, редактирование файлов, поиск) — **ОБЯЗАТЕЛЬНО делать всё самому под ключ** от начала до конца.
* Не перекладывать рутину на пользователя: самостоятельно диагностировать, вносить правки, тестировать и проверять результат.

### 4️⃣ ПРАВИЛО №4: МОНОЛИТНЫЕ СКРИПТЫ И ОЧИСТКА ЭКРАНА
* Если для решения требуется несколько команд, **объединять их в один общий монолитный скрипт/блок кода**, готовый к единовременному запуску целиком.
* В самом начале каждого исполняемого скрипта или блока команд обязательно вызывать команду очистки консоли (`clear` для Bash или `cls` для CMD/PowerShell).
* Всегда явно указывать контекст выполнения:
  - PowerShell (обычный или от имени Администратора);
  - CMD (`.cmd` / `.bat`);
  - Удалённый сервер (с IP-адресом / именем хоста) или WSL/Bash.

### 5️⃣ ПРАВИЛО №5: ЗАЩИТА ОТ ЗАВИСАНИЙ И БЕЗОПАСНЫЕ ТАЙМАУТЫ
* Любая сетевая или фоновая команда обязана иметь жёсткие таймауты. Для SSH обязательно использовать неинтерактивный режим:
  `ssh -o BatchMode=yes -o ConnectTimeout=5 -o ServerAliveInterval=5 -o ServerAliveCountMax=1 user@host "cmd"`
* **Правило 60 секунд:** если операция длится дольше 1 минуты, агент обязан выдать промежуточный статус с оценкой оставшегося времени.
* **Зачистка задач (Zero Dangling Tasks):** перед финальным ответом проверить список фоновых процессов и остановить все лишние или брошенные задачи.

### 6️⃣ ПРАВИЛО №6: ЗВУКОВОЙ СИГНАЛ ПРИ 100% ГОТОВНОСТИ (CHIMES)
* Звуковой сигнал воспроизводится **ИСКЛЮЧИТЕЛЬНО ТОГДА**, когда вся работа завершена, все процессы закончили выполнение и сформирован финальный ответ.
* Стандартный системный звук: `C:\Windows\Media\chimes.wav`, вызываемый в фоне:
  `powershell -NoProfile -Command "(New-Object System.Media.SoundPlayer 'C:\Windows\Media\chimes.wav').PlaySync()"`

### 7️⃣ ПРАВИЛО №7: ОБЯЗАТЕЛЬНЫЙ ОДНОСТРОЧНЫЙ СТАТУС-ТАЙМСТЕМП
В самом конце **каждого сообщения** в одну строку стандартным читаемым шрифтом выводить статус с точным временем и токенами:
* `✅ Done: Started HH:MM:SS • Finished HH:MM:SS • Total: HH:MM:SS (Tokens: ~XXXX response / ~YYYY session)`
* `⚠️ Action Required: Started HH:MM:SS • Finished HH:MM:SS • Total: HH:MM:SS (Tokens: ~XXXX response / ~YYYY session)`
* `ℹ️ Info: Started HH:MM:SS • Finished HH:MM:SS • Total: HH:MM:SS (Tokens: ~XXXX response / ~YYYY session)`

## 🌟 ОБЩИЕ СТАНДАРТЫ

1. **Кодировка:** Исключительно **UTF-8** (без BOM) для всех создаваемых и редактируемых файлов.
2. **Языковой регламент:**
   - Язык общения по умолчанию: всегда **русский язык**, независимо от языка запроса.
   - Исключения: переход на чешский (čeština) или английский (English) **только по прямой просьбе пользователя**.
   - Технический язык: код, имена переменных, коммиты Git, системные пути — всегда на **английском языке**.
3. **Оформление ссылок:** Все упоминания внешних ресурсов, сайтов, файлов или репозиториев GitHub оформлять кликабельными ссылками со стрелочкой `↗` на конце (например: `[Linux_Server_Public ↗](https://github.com/GinCz/Linux_Server_Public)`).
4. **Запрет на рабочий стол:** Не сохранять рабочие скрипты или проекты на системный `Desktop`.
