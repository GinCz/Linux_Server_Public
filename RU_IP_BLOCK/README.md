# RU Block — проверка доступности серверов из России

Сравнивает доступность **существующего TCP-порта публичного IPv4** из российских и зарубежных сетей через Check-Host. Работает с одного Linux-сервера: собственные российские устройства для базовой проверки не нужны.

**Это индикатор возможной фильтрации, а не доказательство блокировки РКН и не проверка работоспособности VPN.** Успешное TCP-соединение не означает, что VPN-протокол или передача данных через туннель работают. Российские точки Check-Host преимущественно размещены в дата-центрах; результат нельзя переносить на всех домашних и мобильных операторов.

## Быстрый запуск

Цель: разовая проверка. Окружение: Linux, Bash, Python 3.8+ и curl. Место запуска: SSH-терминал сервера, например встроенный терминал VS Code Remote SSH. SFTP/FTP-клиент сам команды не выполняет. Root не нужен.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/GinCz/Linux_Server_Public/main/RU_IP_BLOCK/run.sh) --public-checks
```

Ввести **полный IPv4 из четырёх частей** и **существующий TCP-порт**. Имя сервера и окончание IP не угадываются. Для WireGuard/AmneziaWG на UDP нельзя вводить UDP-порт как TCP: это будет другой тест. Можно проверить отдельный уже открытый TCP-порт того же адреса, но это не проверяет UDP/VPN.

Перед вводом адреса выводится предупреждение: IP и порт будут переданы публичному сервису Check-Host и его узлам. Сервис может сохранять отчёты. Ключи, пароли, VPN-профили и журналы ему не отправляются. Если адрес нельзя раскрывать сервису, не запускайте публичные проверки — нужны свои проверяющие устройства.

Скрипт скачивается во временный каталог, его SHA-256 сверяется со значением в launcher. Каталог удаляется после выхода. Launcher с `main` остаётся доверяемым изменяемым кодом; хеш защищает целостность скачанного Python-файла, а не от компрометации репозитория. Если запуск ничего не вывел, проверьте ошибку curl: process substitution не передаёт его код возврата Bash.

На сервере не устанавливаются пакеты, не изменяются VPN, SSH, firewall, маршруты, cron или systemd. Создаются только временные файлы и каталог результатов `./RU_IP_BLOCK_DATA` в текущем рабочем каталоге. Выполняются небольшие сетевые TCP-проверки; необязательный пользовательский `probe_command` имеет собственное поведение.

## Повторные проверки и несколько серверов

Цель: наблюдение каждые 5 минут до Ctrl+C. Окружение: Linux/Bash. Место запуска: SSH-терминал, рабочий каталог с правом записи.

```bash
set -euo pipefail
bash <(curl -fsSL https://raw.githubusercontent.com/GinCz/Linux_Server_Public/main/RU_IP_BLOCK/run.sh) --public-checks --watch
```

Режим работает на переднем плане. Закрытие SSH может остановить его; автоматический запуск после перезагрузки не устанавливается. Для постоянной службы сначала сохраните и проверьте локальную копию, затем отдельно настройте supervisor/systemd. Не скачивайте изменяемый код с GitHub каждые пять минут из cron.

Для нескольких серверов скопируйте `targets.example.json` в локальный `targets.local.json`, замените заглушку реальным публичным IP, укажите порт и добавьте объекты в `targets`. Имена уникальные, только английские буквы, цифры, `_`, `.` и `-`. Максимум 20 целей. Не загружайте заполненную конфигурацию в публичный репозиторий.

Цель: проверка локального списка серверов. Окружение: Linux/Bash. Место запуска: SSH-терминал в каталоге с `targets.local.json`.

```bash
set -euo pipefail
bash <(curl -fsSL https://raw.githubusercontent.com/GinCz/Linux_Server_Public/main/RU_IP_BLOCK/run.sh) --public-checks --config ./targets.local.json --public-checks --watch
```

Опции: `--ip` и `--port` вместо конфигурации; `--name`; `--output /absolute/path`; `--interval 300` (минимум 300 секунд паузы между завершёнными циклами); `--threshold 3`; `--control example.com:443`; `--help`. При неинтерактивном запуске нужен `--public-checks`. Контрольный адрес можно заменить вашим независимым заведомо доступным TCP-сервисом. Его недоступность снижает уверенность результатов.

## Алгоритм и статусы

1. Получить текущий каталог узлов Check-Host. Выбрать до трёх российских и до трёх зарубежных узлов, с разными ASN внутри каждой группы. Реальное число может быть меньше.
2. На выбранных узлах проверить независимый контрольный адрес `example.com:443`.
3. На тех же узлах проверить IP и TCP-порт каждой цели. Ожидание результата ограничено; незавершённые, отсутствующие и некорректные результаты — `NO_DATA`.
4. Сравнить результаты. Ошибка TCP учитывается как свидетельство сетевого отказа только при успешном контрольном соединении с этого узла.
5. После трёх последовательных одинаковых статусов вывести `EVENT` при изменении устойчивого состояния, включая восстановление. Пропуск данных прерывает серию другого статуса. Первое устойчивое состояние также даёт событие.

| Статус | Значение |
| --- | --- |
| `TCP_REACHABLE` | Все выбранные российские узлы (минимум два разных ASN) и хотя бы один зарубежный успешно подключились. VPN не проверен. |
| `RU_RESTRICTION_SUSPECTED` | Отказ минимум в двух российских ASN при успешных контролях и доступности цели за рубежом. Возможна фильтрация или региональная проблема маршрутизации. |
| `RU_NETWORK_FAILURE` | Такой отказ выявлен только в одном российском ASN. |
| `TARGET_OR_ROUTE_FAILURE` | Подтверждённые контролем отказы в РФ и за рубежом без успешного зарубежного подключения; проверить сервис, firewall и маршруты. |
| `PARTIAL_DATA` | Есть успешное российское подключение, но недостаточно покрытия для общего положительного результата. |
| `INCONCLUSIVE` | Недостаточно достоверных данных, нет подходящих узлов, API недоступен или картина неоднозначна. |

В консоли каждый узел показан отдельно: страна, ASN, результат цели и контроля. Значение `confirmed_status` в JSON — последнее устойчивое состояние; оно может отличаться от текущего `status`. Смотрите оба поля и время, а не только старый подтверждённый статус.

Код выхода 0 означает завершённый цикл, **не** доступность сервера. Ошибка аргументов/локальной записи — 2, Ctrl+C — 130. API-отказ сохраняется как `INCONCLUSIVE`, наблюдение продолжается; повтор после обычного интервала, без агрессивных повторов при ограничениях API.

## Локальные данные

- `latest.json`: последний полный отчёт, включая узлы и идентификаторы публичных измерений.
- `history.jsonl`: история циклов; при достижении 5 MB переносится в `history.jsonl.1`, предыдущий архив заменяется. Максимум примерно 10 MB плюс один цикл.
- `state.json`: счётчики последовательных результатов и устойчивое состояние. После длительного перерыва (более двух интервалов) состояние не переиспользуется.
- `.lock`: OS-lock запрещает два одновременных процесса с одним каталогом результатов; автоматически освобождается при выходе/аварии.

На Linux новые файлы создаются с приватной маской 077. Существующий каталог должен принадлежать вам и быть недоступен посторонним. Отчёты содержат реальные IP: не публикуйте их. Для разных независимых запусков используйте разные `--output`.

## Проверка настоящего VPN: расширение

Полная система требует минимум домашнюю и мобильную сеть РФ плюс контрольную точку за рубежом. Проверяющие устройства должны устанавливать настоящий VPN-сеанс, передавать данные и исключать выход напрямую. Сбор результатов должен работать отдельно от проверяемого VPN, а потеря самого устройства означать «нет данных».

Опциональное поле цели `probe_command` — массив аргументов локальной команды, например `["/opt/vpn-check/probe.sh", "test-profile"]`. Команда выполняется **на машине запуска монитора**, без shell, с тайм-аутом 45 секунд. stdout/stderr отбрасываются; секреты не передавайте аргументами. Код 0 означает `PASS`, 1 — `FAIL`, другие коды, отсутствие файла и тайм-аут — `NO_DATA`. Без команды — `NOT_CONFIGURED`. Этот результат отображается отдельно от публичной TCP-классификации и не запускает отдельное уведомление о VPN-отказе.

Контракт вашего адаптера:

1. Использовать отдельный тестовый профиль и уже подготовленный изолированный namespace/контейнер, не менять маршрут SSH-сессии.
2. Проверить handshake/состояние конкретного клиента, затем запросить два независимых адреса через туннель.
3. Проверить ожидаемый маршрут или внешний IP; запретить прямой fallback.
4. Вернуть 0 только после проверки передачи данных; 1 для достоверного отказа VPN; 2 для отсутствия условий проверки.
5. Хранить учётные данные локально и не печатать их. Не оставлять дочерние фоновые процессы.

Готового адаптера для WireGuard, AmneziaWG, OpenVPN или Xray здесь пока нет: он зависит от конкретного протокола и локальных профилей. Запуск с зарубежного сервера не превращает локальный адаптер в российскую точку. Не используйте произвольные загруженные конфигурации: `probe_command` выполняет указанный в них код с вашими правами.

## Дополнительные методы и границы первой версии

Реестр РКН, DNS/TLS с нужным именем, ping, traceroute/MTR, потери/скорость/MTU, серверные журналы и метрики помогают уточнять причину. Отсутствие записи в реестре или успешный ping не доказывают работу VPN. Обычная отправка UDP без ответа также не доказывает блокировку.

Эти методы, резервный провайдер измерений, агентская инфраструктура, dashboard, Telegram/email и systemd-установка **не реализованы в первой версии**. Реализованы публичный TCP-мониторинг, контрольные измерения, история, устойчивые события в консоли и интерфейс локального теста. Скрипт не обходит CAPTCHA и не обещает обнаруживать все виды фильтрации.

Источники и варианты расширения:

- [Check-Host API](https://check-host.net/about/api?lang=en): используемый API и форматы TCP-результатов.
- [Globalping](https://globalping.io/): альтернативные распределённые измерения.
- [RIPE Atlas](https://atlas.ripe.net/docs/apis/rest-api-manual/measurements/creating-measurements/definitions/): маршруты, DNS, TLS и другие типы измерений.
- [OONI Explorer](https://explorer.ooni.org/): контекст ограничений по сетям, не готовая проверка частного VPN.
- [Роскомсвобода: блокировки VPN-протоколов](https://roskomsvoboda.org/ru/analysis/vpn-russia-2023-eng/).

## Проверка разработки

Цель: автономные регрессионные тесты без сетевых запросов. Окружение: Python 3.8+. Место запуска: терминал в каталоге `RU_IP_BLOCK`.

```bash
set -euo pipefail
python3 -m unittest -v test_monitor.py
bash -n run.sh
```

Живой тест провайдера на публичном контрольном адресе не подтверждает доступность ваших серверов. Для этого нужен корректный полный IP, существующий TCP-порт и, отдельно, тест VPN-протокола.
