## ⚡ 2. Новая версия при любом изменении, формат v000 и свойства .exe (Strict Auto-Bump & PE Metadata Standard)
1. **Любое изменение повышает версию:**
   - При **ЛЮБОМ** изменении, исправлении, добавлении или улучшении функций **ВСЕГДА создается следующая рабочая версия** (например, `v002` -> `v003`, `v040` -> `v041`).
2. **Формат номера версии — строго три цифры:**
   - Версия пишется строго буквой `v` и тремя цифрами: например, `v003`, `v030`, `v041`, `v105`.
3. **Запрет указания номера версии в названии установленного файла:**
   - Исполняемый файл программы называется строго: `<AppName>.exe` (а релизный установщик: `<AppName>_Setup.exe` или `<AppName>_vXXX.exe`).
4. **Обязательное и полное заполнение свойств .exe файла (Windows PE Details & Tooltip):**
   - В свойствах каждого `.exe` файла ВСЕГДА и БЕЗ ИСКЛЮЧЕНИЙ прописываются все данные через ресурсы Windows (`VERSIONINFO` / `app.rc` / `AssemblyInfo.cs` / `windres`):
     - **`LegalCopyright` (Авторские права):** строго `VladiMIR+AI` (категорически запрещено писать «Буланцев», «GinCz», «Гот» и т.п.);
     - **`CompanyName` (Организация):** строго `VladiMIR+AI`;
     - **`FileDescription` (Описание файла):** `<AppName>_vXXX` (название приложения, нижнее подчеркивание, строчная буква `v` и три цифры версии, например `GIN-Installer_v030`, `GIN-Voice_v041`, `GIN-NetScan_v015`);
     - **`ProductName` (Название продукта):** `<AppName>_vXXX` (название приложения, нижнее подчеркивание, строчная буква `v` и три цифры версии, например `GIN-Installer_v030`);
     - **`ProductVersion` (Версия продукта):** строго `vXXX` (например `v030`, `v041`);
     - **`FileVersion` (текстовая строка в `StringFileInfo`):** строго `vXXX` (или `0.XXX.0.0`);
     - **`FileVersion` (системная бинарная структура `VS_FIXEDFILEINFO` / `AssemblyVersion` / `FILEVERSION`):** строго `0.XXX.0.0` (например, для `v030` -> `0.30.0.0`, для `v041` -> `0.41.0.0`, для `v001` -> `0.1.0.0`);
     - **Язык ресурсов:** Английский (`English (United States)`, `040904b0` / `langID 0x0409`, `charset 0x04b0` / `1200 Unicode`);
     - **Дата изменения:** сохраняется системная дата сборки / создания файла.
   - **Главное требование:** при наведении курсора мыши в Проводнике Windows во всплывающей подсказке и во вкладке «Подробно» свойств файла номер версии, описание `<AppName>_vXXX` и автор `VladiMIR+AI` должны быть видны сразу и полностью.
5. **Синхронное обновление всех файлов проекта:**
   - Номер версии синхронно обновляется:
     - В ресурсах PE (`app.rc` / `AssemblyInfo.cs` / `rsrc_windows_amd64.syso`);
     - В константах кода (`AppVersion = "v041"`, `AppTitle = "...[v041]"`);
     - В документации (`README.md`, `CHANGELOG.md`, `version.json`, `version.txt`);
     - В реестре Windows (`DisplayVersion`).

## 🖥️ 3. Доставка бинарников — ТОЛЬКО на Рабочий Стол Владимира в MEGA (D:\MEGA\DOCS\desktop)
1. **Тотальный запрет записи на Server_222:**
   - **В сетевую папку на диск на Server_222 мы больше НЕ записываем!** Категорически запрещено записывать скомпилированные файлы на серверные шары DE-222 (`/storage/soft/...`, `S:\soft\...`, `\\DE-222\...`).
2. **Запись ИСКЛЮЧИТЕЛЬНО на Рабочий стол в облако MEGA:**
   - Все новые созданные файлы, утилиты, BAT/CMD-скрипты, PowerShell-лаунчеры, скомпилированные `.exe` и установщики агент **ОБЯЗАН записывать ТОЛЬКО на Рабочий стол Владимира по пути:**
     - Локальный путь у Владимира: `D:\MEGA\DOCS\desktop`
     - Облачный путь в MEGA: `/MEGA/DOCS/desktop/` (команда: `mega-put -c "<file>" "/MEGA/DOCS/desktop/"`).
3. **Принцип самостоятельной раскладки:**
   - **После проверки на Рабочем столе Владимир сам складывает их на место в свои системные папки.** Агент не имеет права самовольно раскидывать бинарники по другим папкам хранилища.
4. **Единственная актуальная версия на Рабочем столе:**
   - На Рабочем столе в `D:\MEGA\DOCS\desktop\` всегда содержится только актуальная копия файла. Все старые версии перед выгрузкой немедленно удаляются:
     ```bash
     mega-rm -f "/MEGA/DOCS/desktop/<AppName>_Setup_v*.exe" "/MEGA/DOCS/desktop/<AppName>_v*.exe" 2>/dev/null || true
     mega-put -c "<AppName>_v<NEW>.exe" "/MEGA/DOCS/desktop/"
     mega-put -c "<AppName>.exe" "/MEGA/DOCS/desktop/"
     ```

## 🔒 4. Разделение Приватных и Публичных Репозиториев (Private vs Public Repo Architecture)
1. **Исходный код — ТОЛЬКО в приватных репозиториях:**
   - Все исходные коды (`.cs`, `.go`, `.c`, `.cpp`, `.h`, `.manifest`, `.rc`, `.syso`, `build.bat`, скрипты сборки и внутренние конфиги) хранятся **ТОЛЬКО В ПРИВАТНЫХ РЕПОЗИТОРИЯХ** (`Secret_Privat` и др.).
   - Категорически запрещено выкладывать исходные коды Windows-приложений в публичный доступ.
2. **Публичные репозитории — ТОЛЬКО описание на английском и установщик:**
   - В публичных репозиториях (`Windows_scripts`, `Linux_Server_Public`, etc.) в папке `Windows/<AppName>/` размещаются:
     - **ТОЛЬКО описание на английском языке** (`README.md` strictly in English);
     - **ТОЛЬКО сам скомпилированный релизный установщик / бинарник** (`.exe`).
     - Никаких файлов исходного кода, исходных скриптов компиляции или вспомогательных служебных файлов проекта в публичных репозиториях быть не должно.

## 📦 5. Стандарт Легковесных Онлайн-Установщиков (<AppName>_Installer.exe)
1. **Единый стандарт именования:**
   - Все компактные онлайн-установщики обязаны строго следовать формату: `<AppName>_Installer.exe` (например: `GIN-VPN_Installer.exe`, `GIN-NetScan_Installer.exe`).
   - Запрещено именование с префиксом действия типа `Install_<AppName>.exe`, чтобы файлы в проводнике Windows и каталогах облака MEGA автоматически группировались по алфавиту рядом с основным приложением.
2. **Характеристики и визуальный стиль:**
   - Нативный компактный C#/.NET исполняемый файл размером **до 50-70 КБ** (без внешних тяжелых фреймворков и библиотек, компиляция встроенным `csc.exe` .NET 4.0/4.8).
   - Обязательное внедрение фирменной иконки приложения (`/win32icon:<AppName>.ico`).
   - Автоматический запрос прав администратора (UAC elevation) при необходимости записи в `C:\Program Files`.
   - Графический интерфейс в темной стилистике с живым индикатором загрузки, процентами и отображением текущего сервера-зеркала.
3. **Динамическое определение версии и защита от устаревших зеркал (Anti-Stale):**
   - Установщик не имеет права слепо скачивать неверсионированный файл `.../<AppName>.exe` с первого доступного сервера без сверки версии.
   - Перед загрузкой установщик опрашивает `version.json` / `version.txt` (с антикэш-штампом `?t=<timestamp>`), определяя точную актуальную версию (например, `v079`) и официальный URL релиза.
   - Загрузка производится в первую очередь по версионированным ссылкам (`<AppName>_v<LATEST>.exe`).
   - После завершения скачивания временный файл проходит обязательную проверку содержимого на наличие сигнатуры целевой версии: если сторонний сервер вернул старый кэшированный бинарник, файл отбрасывается, а установщик переходит к следующему зеркалу (GitHub / CloudCore-191).
4. **Размещение в хранилище:**
   - Легковесный установщик хранится в облачном каталоге утилит `D:\MEGA\WIN-FLASH\Util-WINDOWS\...` вместо 20-мегабайтных монолитных дистрибутивов.

## 🌐 6. Синхронизация с GitHub (GitHub Project Release)
1. **Разделение контента между приватными и публичными репозиториями:**
   - **Приватный репозиторий [Secret_Privat ↗](https://github.com/GinCz/Secret_Privat):**
     - Полный исходный код всех проектов (`Windows/<AppName>/`), скрипты сборки, ресурсы, манифесты и полная документация.
   - **Публичные репозитории ([Windows_scripts ↗](https://github.com/GinCz/Windows_scripts), [Linux_Server_Public ↗](https://github.com/GinCz/Linux_Server_Public)):**
     - В папке `Windows/<AppName>/` размещаются **ТОЛЬКО** описание на английском языке (`README.md` на English) и **сам скомпилированный релизный бинарник/установщик** (`.exe`).
     - Исходный код в публичные репозитории **НЕ ВЫКЛАДЫВАЕТСЯ**.
2. **Своевременная очистка старых бинарников:**
   - Старые бинарники удаляются из репозиториев (`git rm <old_binary>.exe`), чтобы не раздувать размер Git.
