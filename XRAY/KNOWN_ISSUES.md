# XRAY / REALITY — Known Issues

## 2026-08-24 — 3x-ui v3.6.0 / v3.7.0 (Xray-core v26.7.11+) обязательное указание minClientVer = 0.0.0

> ⚠️ **ПРАВИЛО:** В версиях 3x-ui 3.6.0 / 3.7.0+ в настройках каждого Reality inbound обязательно явно вписывать `minClientVer = 0.0.0`.

## 2026-08-07 — Xray-core v26.7.11+ ломает подключение старых клиентов (minClientVer)

**Симптом:**
После обновления Xray-core (через 3x-ui, ядро дошло до `v26.7.28`) клиенты (телефон, компьютер) перестают подключаться к REALITY-инбаунду. И с телефона, и с компьютера — таймаут/отказ на этапе TLS-хендшейка. Предыдущее аналогичное обновление давало ту же проблему, приходилось откатывать ядро.

**Причина:**
Начиная с Xray-core `v26.7.11` изменилось поведение поля `minClientVer` в настройках REALITY. Если поле оставлено пустым, сервер больше не трактует это как "без ограничений" — применяется встроенное значение по умолчанию `26.3.27`. Любой клиент со старым внутренним ядром ниже этой версии получает отказ в подключении. В панели 3x-ui поле выглядит пустым, но на самом деле показывает placeholder `26.3.27`, который реально подставляется движком.

**Где смотреть в панели 3x-ui:**
`Изменить подключение` → вкладка `Безопасность` (Reality) → поле `Мин. версия клиента` (`minClientVer`).

**Фикс (проверено на AWS-12, 18.195.117.12):**
1. Открыть панель x-ui → нужный inbound → `Изменить подключение` → `Безопасность`.
2. В поле `Мин. версия клиента` вписать явно: `0.0.0`
3. Поле `Макс. версия клиента` оставить пустым.
4. Сохранить.

**Важно:** изменение применяется "на лету" — рестарт Xray/сервиса НЕ потребовался, клиенты подключились сразу после сохранения.

**Затронутые сервера:**
Проверено и исправлено на AWS-12. Нужно проверить это же поле на остальных серверах с Xray/3x-ui (222, 109, ALEX_180, 4TON_237, TATRA_9, SHAHIN_227, STOLB_24, PILIK_33, ILYA_221, SO_38, IONOS) при следующем обновлении ядра до v26.7.11 или выше — иначе там повторится тот же обрыв подключений у клиентов.

**Источники:**
- 3x-ui v3.6.0 changelog: bundled core moved to xray-core v26.7.28, breaking change note re: minClientVer / Final Mask.
- Community reports on 3x-ui Reality troubleshooting confirm minClientVer default behavior change.

## 2026-09-23 — Правильное изменение логина и пароля панели 3X-UI (Bcrypt-хэширование)

**Симптом:**
При попытке сменить пароль прямой записью обычного текста (plaintext) в SQLite базу данных `/etc/x-ui/x-ui.db` (`UPDATE users SET password='...'`), веб-панель выдает ошибку:
> ❌ *Неверные данные учетной записи.*

**Причина:**
Современные версии `3X-UI` (начиная с v2.4+) хранят пароли администраторов исключительно в виде **bcrypt-хэша** (`$2a$10$...`). Прямой SQL-запрос `UPDATE` записывает открытый текст, с которым веб-интерфейс не может сопоставить вводимый пароль.

**Правильный способ изменения (CLI через бинарник):**
Для корректной генерации bcrypt-хэша и применения настроек необходимо вызывать встроенный бинарный модуль 3x-ui:

```bash
# 1. Установка нового логина и пароля (автоматически рассчитывает bcrypt):
/usr/local/x-ui/x-ui setting -username "<USERNAME>" -password "<PASSWORD>"

# 2. Перезапуск сервиса для применения изменений:
systemctl restart x-ui

# 3. Проверка успешности хэширования в SQLite:
sqlite3 /etc/x-ui/x-ui.db "SELECT id, username, password FROM users;"
# (В поле password должен отображаться хэш вида $2a$10$...)
```

**Альтернативный способ через интерактивное меню:**
1. Выполнить команду `x-ui` в консоли сервера.
2. Выбрать пункт `7. Reset Username & Password`.
3. Ввести новый логин и пароль.
4. Подтвердить перезапуск панели.
